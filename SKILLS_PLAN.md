# Velvet Grill — Skills Plan

## 1. Purpose

Skills add task-specific procedures. They must complement, not duplicate, `AGENTS.md`, `ARCHITECTURE.md`, and `SECURITY_WORKFLOW.md`.

## 2. Project Skills

### `minimal-diff`

Keep changes small and reviewable.

### `secure-nextjs`

Apply secure Next.js boundaries, validation, authorization, and server authority.

### `supabase-security`

Apply RLS, ownership, migration, and database-security patterns.

### `frontend-interaction`

Create purposeful, accessible, responsive interactions while following `DESIGN_SYSTEM.md`.

### `code-review`

Review correctness, security, maintainability, accessibility, performance, and scope.

### `testing`

Choose the smallest relevant validation set for the change.

## 3. External Skills to Evaluate

Do not install all candidates automatically.

Potential candidates from the current Command Code skill ecosystem include:

- `frontend-design`
- `web-design-guidelines`
- `vercel-react-best-practices`
- `ui-ux-pro-max`
- `supabase-postgres-best-practices`

Prefer one or two high-value design/engineering skills first. Avoid overlapping skills that restate the same rules.

## 4. Skill Rules

1. Keep each `SKILL.md` concise.
2. Use progressive disclosure for long references.
3. Project-local skills are authoritative for Velvet Grill-specific conventions.
4. External skills are supporting guidance, not permission to override security/architecture.
5. Do not install a skill merely because it exists.
6. Review skill source and scope before installation.
7. If two skills conflict, Velvet Grill project rules win.

## 5. Token Efficiency

Do not use Caveman/Ponytail as project skills. They are 9Router features, not Command Code-native skills.

If token reduction is desired later, first optimize task scope and project context. Only introduce routing/token middleware when it solves a measured problem.
